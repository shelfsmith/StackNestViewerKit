# StackNest の参照ファイル（.stacknestbook）— 版 1

**日本語** | [English](BookReferenceFormat.en.md)

外部ビューアの作者向けの文書です。StackNest が対応した外部ビューアへ本を渡すときの、対応の宣言・参照ファイルの形式・API の約束を書きます。

Swift のビューアは、ここに書いたことをすべて実装した StackNestViewerKit を使えます（[README](../README.md)）。ほかの言語のビューアは、この文書から直接実装できます。[Samples](Samples) に参照ファイルの例（読み手が断るべきものを含む）があります。

## 流れ

1. 利用者が StackNest で「StackNest と読書位置を同期する（対応アプリのみ）」を ON にし、画像の本を外部ビューアで開く設定にする。
2. StackNest は、そのビューアが `Info.plist` で対応を宣言しているときだけ（[対応の宣言](#対応の宣言)）、本のファイルの代わりに **参照ファイル**（拡張子 `.stacknestbook`）を書き、外部ビューアで開く。開くビューアは、アーカイブ・フォルダ・画像の本ではそれぞれの種類の指定、PDF（ローカル・リモートとも）とリモートの画像だけの EPUB では「アーカイブ」の指定（ローカルの EPUB は参照ファイルを使わず、従来どおりファイルで開く）。
3. ビューアは参照ファイルに書かれた API から、ページを 1 枚ずつ取って表示し、読み進めたページを書き戻す。要求にはビューアの名乗りを付ける（[名乗りのヘッダ](#名乗りのヘッダ)）。
4. StackNest は参照ファイルを渡してから一定時間後（既定 15 秒）に一度だけ、そのトークンが使われたかを確かめる（[読まれたかの確認](#読まれたかの確認)）。

## 対応の宣言

**この宣言は必須です。** 対応するビューアは、自分の `Contents/Info.plist` に次のキーを置いてください。

```xml
<key>StackNestViewerSupport</key>
<dict>
  <key>referenceFormatVersions</key>
  <array><integer>1</integer></array>
</dict>
```

- `referenceFormatVersions` には、読める参照ファイルの版を整数で並べます。StackNest は自分が書ける版（今は `1`）との**共通の最大の版**を選び、参照ファイルの `version` に書きます。たとえば `[1, 2]` と宣言したビューアには、StackNest が版 2 を書けるようになれば版 2 で、それまでは版 1 で書きます。
- StackNest は渡す前に、そのビューアの `Info.plist` を直接読みます（LaunchServices の登録やキャッシュには頼りません）。次のどれかなら「未対応」として、トークンを出さず参照ファイルも作らず、従来どおり本を渡します（ローカルの本はファイルのまま、リモートの本は StackNest の内蔵ビューアで開きます）。
  - キーが無い、`dict` でない、`referenceFormatVersions` が配列でない
  - 共通の版が無い
- 配列の中の整数でない要素（真偽値・小数・文字列）と 0 以下の値は無視します。
- 参照ファイルの型を開けるという宣言（`CFBundleDocumentTypes`・UTType）は、**対応の判定には使いません**。どんなファイルでも開けると宣言しているアプリを、対応アプリと取り違えないためです。

## 型

| 項目 | 値 |
|---|---|
| 拡張子 | `stacknestbook` |
| UTType | `app.shelfsmith.stacknest.book-reference`（`public.json` に適合。StackNest が宣言する） |

参照ファイルを書類として受け付けるには、この型を `Info.plist` の `UTImportedTypeDeclarations` で取り込み宣言し、`CFBundleDocumentTypes` で書類の種類として受け付けてください（`application(_:open:)` に届きます）。StackNest は `open` でアプリを名指しして渡すので、順位（`LSHandlerRank`）は `Alternate` で足ります。これは Finder での見え方とファイルの受け取りのためで、対応の判定には上の「対応の宣言」が要ります。

## 中身（UTF-8 の JSON）

```json
{
  "format": "stacknest-book-reference",
  "version": 1,
  "title": "本の題名",
  "book": "http://127.0.0.1:51234/api/v1/libraries/<lib-uuid>/books/<id>",
  "token": "<本専用のトークン>",
  "expiresAt": "2026-10-31T12:00:00Z",
  "pageCount": 180,
  "direction": "rtl",
  "startPage": 41
}
```

| 項目 | 型 | 意味 |
|---|---|---|
| `format` | 文字列 | 常に `stacknest-book-reference`。違えば開かない |
| `version` | 整数 | 形式の版。宣言した版のうち StackNest が選んだもの（この文書は `1`）。**読めない値なら開かない** |
| `title` | 文字列 | 本の題名（窓の題名などに使う） |
| `book` | 文字列（URL） | 本の API の基点。下の 4 つの API はこれに続ける |
| `token` | 文字列 | その本専用の読み取りトークン。`Authorization: Bearer <token>` で渡す。使う文字は RFC 6750 の `b64token`（英数字と `-._~+/`、末尾にだけ `=`）だけで、ほかの文字を含むファイルは読み手が断る |
| `expiresAt` | 文字列（ISO 8601） | トークンの有効期限（発行から 30 日）。StackNest は UTC の `Z`・小数秒なしで書く。読み手は小数秒と `+09:00` のような時差付きも読むが、時差の無い時刻は読まない |
| `pageCount` | 整数 | 開いた時点のページ数（正は `manifest`） |
| `direction` | `"rtl"` / `"ltr"` | 開いた時点の読む方向（正は `manifest`） |
| `startPage` | 整数（0 始まり） | 開いた時点の読書位置。ここから開く。`manifest` を読んだら、その `pageCount` に合わせて `0`…`pageCount - 1` に収めてから開く（本のページが減っていることがある。Swift のビューアは `clampedStartPage`） |
| `handoff` | オブジェクト（任意） | いっしょに渡した本の組（`{"id": …, "index": …, "count": …}`）。複数の本を一度に渡したときだけ付く。[いっしょに渡した本](#いっしょに渡した本handoff)を見る |

- 知らない項目は読み飛ばしてください（後の版で項目が増えても開けるように）。
- `title` と `direction` は無くても開きます。`title` が無い、または文字列でないときは空の題名として扱い、`direction` が無い、または `"rtl"`・`"ltr"` 以外の値なら参照ファイルの向きは使いません（開いた後の読む方向は `manifest` の `direction` に従います）。`handoff` も無くてよく、形が下の約束から外れていれば無いものとして扱い、1 冊として開きます。それ以外の項目（`format`・`version`・`book`・`token`・`expiresAt`・`pageCount`・`startPage`）が無い、または型が違うファイルは開きません。
- `version`・`pageCount`・`startPage`（と `handoff` の `index`・`count`）の「整数」は、JSON の数のうち真偽値でなく、小数部が無く（`5.0` は `5` として読む。`5.5` は整数でない）、絶対値が 10^15 未満のものです。
- 読み手は次のファイルを**断ります**（利用者には「StackNest から開き直してください」と案内してください）。
  - 読み出せない（開けない・読めない）、大きさが 1 MiB（1,048,576 バイト）を超える、または JSON のオブジェクトとして読めない
  - `format` が `stacknest-book-reference` でない、または `version` が 1 未満（壊れたファイル）
  - `version` が無い・整数でない、または読めない版（新しい版）。どちらも「読めない版」として扱います（「アプリを更新してください」と案内してよい）
  - `book` が無い・文字列でない・URL として解釈できない、または `http`・`https` 以外のスキーム、空のホスト、問い合わせ（`?`）、断片（`#`）、資格情報（`user:pw@`）のどれかを持つ。問い合わせや断片があると、後ろへ足す `manifest` などが飲まれて別の宛先の要求になり、資格情報は宛先の取り違えの種になるため
  - `token` が空、または `b64token` の文字以外を含む（`=` だけの並びも断る）
  - `expiresAt` が読めない形（時差の無い時刻など）
  - `pageCount` が整数でない、負、または 100,000 を超える（0 は許す）
  - `startPage` が整数でない、負、または 10^15 以上。10^15 未満で `pageCount` を超える値は断らず、`0` から `pageCount - 1` に収めて開く
- 期限（`expiresAt`）を過ぎたファイルは、読み込み自体は通り、期限切れとして報告されます。StackNestViewerKit は、期限切れの参照ファイルでもセッションを作れます（`init(contentsOf:)` は成功します）が、最初の要求（`manifest()` など）が通信せずに期限切れ（`expired`）で失敗します。読み手は期限を確かめて、利用者に「StackNest から開き直してください」と案内してください。
- 形式の検査は、`book` のホストを絞りません（LAN や IPv6 のアドレスも形式としては正しい）。接続先を絞るかどうかは読み手の判断です（StackNestViewerKit は既定で 127.0.0.1 と `::1` にだけつなぎます。下の「ビューアへのお願い」）。
- [Samples](Samples) で、`reference-v1`・`reference-v1-handoff`（組の付いたもの）・`reference-v1-unknown-keys`・`reference-expired`・`reference-lan-host`・`reference-ipv6-zone` は形式としては読めます（`reference-expired` は期限切れで最初の要求が失敗するため、`reference-lan-host` と `reference-ipv6-zone` は既定の宛先の制限で、StackNestViewerKit は開きません）。`reference-credentials`（資格情報つき）・`reference-malformed`（壊れた JSON）・`reference-v2`（読めない版）は断ります。
- ローカルの書庫の本では `book` が `http://127.0.0.1:<port>/api/v1/libraries/<lib>/books/<id>` になります（その Mac の中だけで待ち受ける口）。
- **リモートの書庫の本も、`book` は `http://127.0.0.1:<port>/api/v1/relay/<relayID>` になります**（試用）。StackNest がこの口で受けた要求を、リモートのサーバへ中継します。実測では、サンドボックスのビューアが `NSAllowsLocalNetworking` の下で届くのは 127.0.0.1 とプライベートのアドレスまでで、Tailscale のアドレス（100.64.0.0/10）や公開のアドレスへの平文の HTTP は App Transport Security に止められます。そのため StackNest がリモートの本を中継し、ビューアはいつも手元の 127.0.0.1 につなげば済むようにしています。下の 4 つの API はローカルの本と同じで、ビューアは `book` の形を見分ける必要はありません。リモートのサーバの鍵はビューアには渡りません（参照ファイルの `token` は中継用の鍵で、`expiresAt` は発行から 30 日とリモートの鍵の期限の早い方です）。
- この口は StackNest が起動していて設定が ON のあいだだけ動き、ポートも変わることがあります。接続を拒まれたら、「StackNest から開き直してください」と表示してください。StackNest を終了すると中継は消えるので、その後の要求は **401** になります（中継の期限が切れたときも同じです。「StackNest から開き直してください」と表示してください）。中継の取り次ぎでリモートのサーバに届かない・応答が大きすぎる・リダイレクトされたときは **502** です。中継の `progress` に 64 KiB を超える本文を送ると **413** で、リモートには取り次ぎません。リモートの応答（403・404 や `X-Library-Locked` を含む）はそのまま返します。リモートが中継を **401・403** で断ったら（パスワードの変更・接続の取り消しなど）、StackNest はその応答を返したうえで中継を閉じるので、以後の要求はキャッシュにあるページも含めて **401** になります（「StackNest から開き直してください」と表示してください）。

## API

すべて `Authorization: Bearer <token>` と、下の[名乗りのヘッダ](#名乗りのヘッダ)を付けます。

| 要求 | 応答 |
|---|---|
| `GET {book}/manifest` | `{"pageCount": 180, "direction": "rtl", "format": "archive", "etag": "…"}`（ほかの項目は読み飛ばす）。`format` は参考情報で、値は `archive`・`folder`・`image`・`text`（PDF と画像だけの EPUB）。どの値でも `pages/{n}` で同じように読んでください |
| `GET {book}/pages/{n}` | `n` 番目（0 始まり）のページの画像（JPEG・PNG・WebP など。`Content-Type` を見る）。`?maxw=<幅>` で縮小を頼める。通常は `ETag` が付き、付いているときは `If-None-Match` で 304 を受けられる（中継のときは付かないことがある。[中継のページ](#中継のページ)を見る） |
| `GET {book}/cover` | 表紙の画像（`?maxw=` 可） |
| `POST {book}/progress` | 本文 `{"page": n}`（0 始まり）で読書位置を書き戻す。200 |

- このトークンで使えるのは上の 4 つだけです。ほかの URL・ほかの本は **403** です。
- 自分の本への **403** でも、ヘッダ `X-Library-Locked: 1` が付いているときは、参照ファイルを作った後に書庫のロックが変わった（パスワードを変えた、または施錠した）ことを表します。「StackNest でライブラリを解錠し、StackNest から開き直してください」と表示してください（ビューアの中では「書庫」がアーカイブの意味になるため、表示には「ライブラリ」を使います）。
- **401** はトークンの期限切れ（または取り消し）です。トークンを出した後に、その本の番号に別の本が入った（本を消してから別の本を取り込んだ）ときも 401 になります。「StackNest から開き直してください」と表示してください。
- **404** は本が見つからない（書庫から消えた、サーバが書庫を閉じた）ことを表します。`pages/{n}` では範囲外のページ番号も **404** です。`cover` の **404** は、本に表紙の画像が無いことも表します。
- `pages/{n}` でページを描画できないときは **500**、`progress` に負のページを送ると **400** です。

### 中継のページ

リモートの本（`book` が `/api/v1/relay/` の下）では、`maxw` を付けない（または `maxw=1600` の）`pages/{n}` は、StackNest の内蔵ビューアと同じ画像を返します。StackNest は中継したページを手元のキャッシュに入れて内蔵ビューアと分け合い、本を渡した後は、StackNest の設定に従って、読んでいるあたりのページ（設定によっては全ページ）を裏で先読みします。

- 幅が 1600 ピクセルを超えるページは、長い辺が 1600 ピクセル以内になるように縮み、JPEG に変換されて届きます（PNG・WebP のページも）。幅 1600 ピクセル以下のページはそのまま届きます。元の大きさや形式を仮定せず、`Content-Type` を見てください。
- この応答には `ETag` が付かないので、`If-None-Match` を使わずに取り直してください（キャッシュから返すので速い）。
- ほかの `maxw` を付けた要求は、そのままリモートのサーバへ取り次ぎ、キャッシュしません。
- `manifest`・`cover`・`progress` は常にそのまま取り次ぎます。`manifest` には必ず `etag` が付きます。

## 名乗りのヘッダ

**このヘッダは必須です。** 本の API を呼ぶたびに、次のヘッダを付けてください。

```
X-StackNest-Viewer: <bundle id>/<ビューアの版>; format=<参照ファイルの版>[; kit=<StackNestViewerKit の版>]
```

例: `X-StackNest-Viewer: com.example.viewer/1.80; format=1; kit=0.1.0`

- `<ビューアの版>` は `CFBundleShortVersionString` などの、利用者に見える版です。`format=` には、開いた参照ファイルの `version` を書きます。
- 引数は `;` で区切った `key=value` で、`format` が先です。StackNest は知らない引数を読み飛ばすので、後から引数を足せます。
- `kit=` は StackNestViewerKit が自分で付けます。部品を使わずにこの文書から実装するビューアは付けなくてかまいません。
- bundle id・ビューアの版・部品の版に使う文字は `A-Z a-z 0-9 . _ + -` だけです（StackNestViewerKit はほかの文字を `_` に替えます）。bundle id とビューアの版は 64 文字まで、部品の版は 16 文字までなので、全体が 200 文字に収まります。
- StackNest はヘッダが無くても要求を拒みません。トークンが初めて使われたときに、その日時とこのヘッダの値を一度だけ記録します（印字できる ASCII だけを残し、200 文字で切ります）。記録は、設定の「外部ビューア」の節で、どのビューアの対応を確認できたか（日時と版）を示すのに使います。記録には `kit=` を含む値がそのまま残り、設定に出すのは bundle id・ビューアの版・`format` です。

## いっしょに渡した本（handoff）

利用者が StackNest で複数の本を選んで外部ビューアで開くと、StackNest はそのビューアへ渡す本ごとに参照ファイルを書き、どの参照ファイルにも同じ組の印を入れます。

```json
"handoff": {"id": "ZXhhbXBsZS1oYW5kb2Zm", "index": 1, "count": 3}
```

| 項目 | 型 | 意味 |
|---|---|---|
| `id` | 文字列 | 組の印（8〜64 文字の ASCII の英数字と `-`・`_`）。同じ組の参照ファイルは同じ値。等しいかだけを比べる |
| `index` | 整数 | 組の中での位置（0 始まり）。StackNest の一覧で選んだ並び（一覧の表示順） |
| `count` | 整数 | 組の冊数（`index` < `count` ≤ 10,000） |

- 1 冊だけ渡すときは付きません。渡す先のアプリが本の種類（書庫・フォルダ・画像）で違うときは、アプリごとに別の組になります。
- StackNest は組の参照ファイルを、アプリごとに 1 回の `open` でまとめて渡します。ただし、届き方（1 回の `application(_:open:)` で届くか、何回かに分かれるか、届く順）には頼らないでください。同じ `id` のものを集め、`index` で並べてください。`count` に満たないまま待ち続けないでください（組の一部が渡せなかったときは、その本の参照ファイルは届きません。最初の 1 冊が届いてから数秒で揃わなければ、届いた分で進めてください）。
- 組をどう開くかはビューアが決めます（先頭を開いて残りを「次の本」に並べる、全部を別々の窓で開く、など）。**すぐに開かない本も、受け取った時点でそれぞれの `manifest` を取ってください**。StackNest は参照ファイルごとに、渡してから 15 秒後にトークンが使われたかを確かめます（[読まれたかの確認](#読まれたかの確認)）。
- 形が上の約束から外れた `handoff`（`id` の文字・長さ、`index`・`count` の範囲や型）は、無いものとして扱います（参照ファイルは断らず、1 冊として開く）。StackNestViewerKit は `nil` にします。
- `handoff` を知らない古いビューアは、知らない項目として読み飛ばし、届いた参照ファイルを今までどおり 1 冊ずつ開きます。

## 読まれたかの確認

- StackNest は参照ファイルを渡してから一定時間後（既定 15 秒）に一度だけ、そのトークンが使われたかを確かめます。ローカルの本も中継するリモートの本も、手元の 127.0.0.1 の口の記録で確かめます（中継を使わずにリモートのサーバへ直接つなぐ形でだけ、トークンを発行した接続から `GET /api/v1/viewer-tokens/{tokenID}`（状態の API）で確かめます）。
- 中継の鍵の「使われた」は、ビューアが有効な中継の鍵で 127.0.0.1 の口に**届いた**ことを指します（ページを読み込めたことではありません。リモートが 502 でも、`manifest` の要求が届けば記録されます）。中継の鍵の記録は実際の書庫・本を持たず、見張り用の値（書庫 `"relay"`・本 0）を持ちます（ビューアが気にする必要はありません）。
- まだ使われていなければ、StackNest は「〈アプリ名〉が本を読み込んでいません」と知らせ、従来の開き方（ローカルの本はファイルのまま、リモートの本は内蔵ビューア）で開くボタンを出します。トークンは取り消さないので、ビューアが遅れて読み始めても動きます。
- 参照ファイルを受け取ったら、まず `manifest` を取ってください（開いたことが早く伝わります）。

## ビューアへのお願い

- `startPage` から開いてください。ビューア自身の読書位置の記録があっても、参照ファイルの `startPage` を優先してください。
- ページを移るたびに書き戻すのではなく、数秒まとめて `progress` に送ってください。閉じるときにも送ってください。
- すべての要求に[名乗りのヘッダ](#名乗りのヘッダ)を付けてください。
- トークンは秘密です。ログに出さず、ほかへ送らないでください（詳しくは下の「セキュリティ上の注意」）。
- 通信は HTTP です（LAN か Tailscale での利用を前提にしています）。App Transport Security で 127.0.0.1 と LAN への平文 HTTP を許可し、App Sandbox を使うならネットワーク（クライアント）の権限を付けてください。
- StackNestViewerKit は、既定では `127.0.0.1` と `::1` にしかつなぎません（StackNest はローカルの本も中継するリモートの本も、`book` を 127.0.0.1 に書くため）。ほかのホストへつなぐ必要があるビューアは、明示して許可します（`allowedHosts`）。
- StackNestViewerKit は、既定では `book` のパスが StackNest の書く 2 つの形（`/api/v1/libraries/<lib>/books/<id>` と `/api/v1/relay/<relayID>`）のときだけ要求を出し、ほかは要求を出さずに `invalidReference` で断ります（「StackNest から開き直してください」）。各区切りは空でなく、`.`・`..` でなく、英数字と `-._~` だけ（パーセントエンコードを含まない）で、末尾のスラッシュは 1 つまでです。ほかの形の基点へつなぐ必要があるビューアは、明示して許可します（`allowsAnyBookPath`）。この文書から直接実装するビューアにも、同じ確かめを勧めます（下の「セキュリティ上の注意」）。

## セキュリティ上の注意

- トークンは参照ファイルの中に**平文**で入っています。StackNest は参照ファイルを権限 600（本人だけ読める）、置き場のディレクトリを 700 で書きます。有効期限は 30 日です。ビューアはトークンをほかの場所へ写さず、ログにも出さないでください。
- `book` の基点が LAN 上の `http://` のアドレスのとき、トークンは暗号化されずに流れます。StackNest は HTTP だけを提供します。素の LAN では暗号化されないので、Tailscale 越しの StackNest のリモート接続を使うと通信が暗号化されます。リモートの本を中継するとき（試用中の既定）は、ビューアとの通信は 127.0.0.1 の中だけで、StackNest とリモートのサーバの間は StackNest のリモート接続と同じ道を通ります。
- 基点には IPv6 のアドレスが入ることがあります（例: `http://[fe80::1%25en0]:51234/…`）。ビューアは角括弧で囲まれたホスト（ゾーン ID を含む）を解釈できるようにしてください。
- トークンは参照ファイルの `book` が指すオリジン（スキーム・ホスト・ポート）にだけ送ってください。リダイレクト先や別のホストへ付けて送らないでください。
- 宛先を 127.0.0.1 に絞っても、ポートとパスは参照ファイルが決めます。書き換えた参照ファイルの `book` が 127.0.0.1 の別のサービスの道を指すと、ビューアはそのサービスへトークン付きの決まった形の要求（`GET {book}/manifest`・`POST {book}/progress` など）を送ってしまいます。`book` のパスが StackNest の書く形（上の 2 つ）であることを確かめてから要求を出してください（StackNestViewerKit は既定でそうします）。
- 使われたかの照会（`GET /api/v1/viewer-tokens/{tokenID}`）は、トークンを発行した主体だけが読めます。ただし共有サーバを固定トークン（グラント無し）で動かしているときは主体を区別できないので、同じトークンを持つ接続はどれも、そのトークンで発行した本専用トークンの使用の状況（日時と名乗りだけ）を読めます。127.0.0.1 の口でも、ローカルコントロールが ON なら CLI・MCP のトークンが、App の出したトークンの状況を読めます。どちらも名乗りのヘッダの値が見えるだけで、本の中身やトークンは出ません。
